Open source · MIT · zero dependencies

Catch the leak before you publish.

Agent packages ship prompts, tool definitions and configuration. One leaked email address, one absolute path from your laptop, one skill reference to a directory that no longer exists — and you find out after publishing. agent-pkg-audit is a command-line gate that catches those first. It exits non-zero, so CI can block a bad release.

npx agent-pkg-audit ./my-agent-package

01The problem

Every rule in this tool corresponds to a failure that actually happened while running a multi-window agent system as a pre-publish gate.

Before — you find out too late

A credential sits in a skill file. An absolute path points at one machine. A manifest is missing a key, so the package loads on your box and silently fails on everyone else's. The review happens after the release, if at all.

After — the gate runs first

One command scans the whole package, prints what it found, and exits 1 if anything is wrong. Put it in prepublishOnly and a bad package can never reach the registry.

02What it checks

Five passes over the package tree. Read-only, deterministic, no network calls.

PassWhat it catches
A · StructurePlugin manifest validity and required keys, agent files present, agent frontmatter carries name and description, agent body not empty
B · Secret / PII gateEmail addresses, hard-coded credentials, private key material, national ID numbers, absolute local paths. Matches next to an explicit redaction marker are ignored, so placeholders stay quiet
C · PortabilityHarness-specific coupling — warns when a package only runs on one agent platform
D · IntegrityIf a MANIFEST.json is present, every listed file is SHA256-verified against it
E · Static fault proxiesThe statically-detectable subset of a 15-class multi-agent failure taxonomy: role ambiguity, broken cross-references, configuration faults, instruction drift

03See it work

A package with one missing manifest key, one email, one absolute path, one pasted key, one unfinished marker and two dangling skill references:

agent-pkg-audit 
# agent-pkg-audit report
> repository: /work/my-agent-package
> packages detected: 1

- BLOCK  agents/assistant.md -> [secret_assignment] API_KEY = "sk-live-9f3a..."

- WARN   agents/assistant.md -> [broken-xref] skills[nonexistent-skill] directory does not exist

- packages: 1
- blockers: 4
- warnings: 4

> exit 1 (blockers found — fix before publishing)

04Install & use

One command, no install-time dependencies, works on Linux, macOS and Windows.

Run it once

# via npx, no install
npx agent-pkg-audit ./my-agent-package

# or install globally
npm install -g agent-pkg-audit
agent-pkg-audit ./my-agent-package

Wire it into CI

# .github/workflows/release.yml
- name: Audit agent package
  run: npx agent-pkg-audit . --report audit-report.md

Or make it impossible to publish a bad package

// package.json
{
  "scripts": {
    "prepublishOnly": "agent-pkg-audit ."
  }
}

05Protect your own project

Real names, internal codenames and private vocabulary belong to your project — not to a general-purpose tool. The shipped defaults stay neutral; you add yours with --rules. 

{
  "_comment": "documentation keys are ignored",
  "persona": [
    {
      "id": "persona_real_name",
      "severity": "blocker",
      "pattern": "Your\\s+Name",
      "message": "real name inside runtime content"
    }
  ],
  "codename": [
    {
      "id": "internal_codename",
      "severity": "warning",
      "pattern": "(?:PROJECT|TEAM|INTERNAL)",
      "message": "internal codename"
    }
  ]
}

persona applies to runtime content only — a name in a system prompt is a leak, the same name in a README signature is attribution.   codename applies everywhere.   except — a match is ignored if any of these regexes matches it.

06Design guarantees

Four properties, and they are testable — the package passes its own gate in CI.

Read onlyThe tool never writes to the audited tree. --report writes only to the path you give it.
Zero dependenciesPython standard library only. No pip install, no transitive supply chain.
DeterministicSame input, same output, same exit code. No network calls, no clock, no randomness.
PortableRuns on Linux, macOS and Windows. Ships as an npm package with a Python fallback.
